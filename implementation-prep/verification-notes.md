# 網站驗證紀錄

## 2026-08-26：公開路由與 RWD

- 首頁在桌面與 375px 行動版皆維持完整視覺層級；五部門、招生入口與研究檔案入口可讀，沒有可見的非必要水平捲動。
- 原先公開首頁的招生入口指向 `/recruitment`，但路由僅有 `/apply`，導致 404；已新增 `/recruitment` 相容路由並以行動版截圖確認修正後可正常載入。
- 招生頁在行動版可呈現校內／校外選項與目前未開放招生梯次的空狀態；帳號頁可正常顯示登入與啟用入口。
- 公告、活動頁的空狀態清楚說明後續發布與資料範圍規則，未以虛構內容填充。
- 社員與管理工作區在未登入狀態正確阻擋存取；管理工作區已新增社長治理登入入口，供暫代網站負責人使用既有治理登入。
- 以社長治理帳號檢查後，管理工作台可載入治理稽核、公告、活動、專案、成員指派與資源管理模組；招生治理頁的首屏載入提示由 `auth.me` 非同步身分查詢所觸發，並非既有資料服務錯誤。
- 發現並修正 `auth.me` 曾原樣回傳使用者列的風險：現已明確移除 `passwordHash`，並以自動測試鎖定此安全要求。
- 正式建置採路由層級延遲載入；公開首頁初始 JavaScript 產物約為 663 kB（gzip 約 193 kB），較重的研究檔案頁改為獨立約 497 kB chunk（gzip 約 126 kB），不再阻塞公開首頁載入。
- 已以 1280px 桌機檢查首頁、`/apply`、`/recruitment`、`/account`、`/announcements`、`/events`、`/workspace`、`/manage/workspace`、`/manage/recruitment` 與 `/research`。公開路由與研究檔案皆正常呈現；招生別名與正規路由一致；目前無公告、活動、梯次、專案、資源或申請資料時，均呈現說明清楚的空狀態而未虛構真實資料。
- OAuth 管理者可進入工作區與招生治理頁。工作區已顯示治理、內容、活動、專案與資源管理模組；招生治理頁已顯示正確的「沒有招生申請」狀態，以及交易 Email 未設定的安全提示。
- 已以 375px 行動版重複檢查同一組十條路由。公開首頁採單欄資訊節奏，招生、帳號、公告與活動頁保留可讀的首要操作；社員工作區與社長管理表單改為直向堆疊，未見可見的水平溢位或控制項截斷；招生治理空狀態與研究檔案亦可在手機寬度正常呈現。
- 角色與後端權限邊界以自動測試驗證：OAuth `admin` 可繞過部門檢查執行治理工作；具有效指定 permission group 的社團幹部可使用對應模組；未具該群組的一般社員會被後端拒絕。權限計算亦驗證無關部門權限不可越權，社長可執行全域治理操作。
- 在完整路由截圖驗收後，檢查最新 800 筆網路紀錄及 500 筆瀏覽器主控台紀錄，未發現新的 4xx／5xx、tRPC Client Error、SyntaxError 或 API Query／Mutation Error。開發服務在重啟後已完成 OAuth 初始化並正常監聽於本機埠。
- 新增的 context 回退測試驗證：當 OAuth 未識別使用者而 `club_session` 有效時，系統會安全載入帳號狀態為 active 的社團社員身分，供受保護的社員與幹部程序使用；本輪共 7 個測試檔、17 項測試通過，並已再次完成正式建置。
- 另以 React 伺服器端渲染測試驗證社員工作區的前端分流：未登入者只會看到社員登入入口；登入的一般社員會進入「我的學習與實作」工作區，並可看到依授權範圍而定的專案與資源空狀態。Vitest 已收錄這類前端測試；最終結果為 8 個測試檔、19 項測試全數通過，且正式建置成功。
- 已建立正式發布就緒文件，載明發布後建立每日 Heartbeat、回填 `scheduleCronTaskUid`、延後啟用交易 Email 及 D-15 治理簽核的作業。最終待辦已重新檢閱，所有開發、驗收、文件與版本保存項目均已完成標記；實際平台排程建立則明確列為部署完成後的營運步驟。
