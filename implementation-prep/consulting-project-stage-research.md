# 管理顧問專案階段切分：研究基線

## 查核來源與發現

| 來源 | 與本案相關的發現 |
| --- | --- |
| [PMI：Essential project management for consultants](https://www.pmi.org/learning/library/essential-project-management-life-cycle-tactics-7767) | 顧問專案核心從問題／情境識別，延伸至方案或替代方案搜尋與選定方案的發展與執行；並強調利害關係人、範圍、風險、溝通與管理支持。 |
| [TCGen：Consulting Deliverables](https://www.tcgen.com/articles/consulting-deliverables/) | 常見流程包括 discovery、analysis、planning、implementation、evaluation；專案章程、路線圖、可衡量里程碑與品質審查是可追蹤交付的關鍵。 |
| [Rework：Strategy Consulting Process](https://resources.rework.com/libraries/professional-services-growth/strategy-consulting-process) | 策略顧問可分為 discovery／情境評估、策略分析、策略發展、選項分析與建議、實施規劃五個相互銜接的階段。 |
| [Atlassian：Project management phases](https://www.atlassian.com/work-management/project-management/phases) | 一般專案生命週期將啟動、規劃、執行、監控與結案作為不同治理工作；本案可保留此治理觀點，但以顧問交付物取代純專案管理術語。 |

## 對 FJUBAC 的初步含義

不建議僅沿用「啟動、規劃、執行、結案」四段，因為這會把**資料診斷**與**建議決策**壓縮在同一個「執行」狀態，導致專案生、幹部與企業端難以分辨目前是在蒐證、推導洞見、選擇方案，還是在完成交付。較合適的是保留五個以顧問產出為主的關卡，並將每一階段的文件、審查與退回規則清楚綁定。
