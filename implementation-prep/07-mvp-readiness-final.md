# 07｜MVP 開發就緒報告（定版）

**定版狀態：** 可進入 MVP 的設計、資料庫與 staging 開發。  
**產品決策者：** 社長。  
**暫代網站負責人：** 社長。  
**production 上線狀態：** 需在上線前完成暫時資產持有與復原方案；D-15 的共用信箱、共同持有與 MFA 正式化延後至下一次 MVP。

## 一、已定版的 MVP 內容

| 範圍 | 定版內容 | 狀態 |
| --- | --- | --- |
| 公開資訊 | 首頁、社團介紹、五部門介紹、公告、活動列表與活動詳情。 | 可開發。 |
| 招生與會員 | 校內／校外獨立招生梯次、申請表、書審、面試、最終核准與帳號啟用。 | 可開發。 |
| 帳號與登入 | 校內：學號＋學校信箱認證碼；校外：外部 Email＋認證碼；驗證後設定或修改密碼。 | 可開發。 |
| 社員與專案生 | 有效社員才可被指派為專案生；專案生可讀取所屬專案資料並參與專案實作。 | 可開發。 |
| 活動 | 預設社員；可設定公開、專案限定或幹部限定；包含名額、候補、取消與基本出席。 | 可開發。 |
| 資源 | 公開／社員／專案／幹部四級可見範圍。 | 可開發。 |
| 幹部與組織 | 五部門、部長／指定幹部／一般幹部、任期開始與結束、提醒與自動撤權。 | 可開發。 |
| RWD 與可近用性 | Mobile-first；手機可完成招生申請、認證、登入、活動報名與專案資料讀取。 | 可開發。 |

## 二、五部門定版組織模型

| 部門 | 核心系統責任 | 主要資料範圍 |
| --- | --- | --- |
| 人才發展部（Talent Acquisition & Engagement） | 校內／校外招生、書審、面試、社員互動。 | 招生梯次、申請、書審、面試；最終核准由社長保留。 |
| 專案開發部（Project Development & Management） | 專案建立、專案生指派、專案營運。 | 專案、專案指派、所屬公告與專案資源。 |
| 對外發展部（External Affairs） | 對外合作、對外活動與聯絡窗口。 | 受指派的公開／對外活動與合作內容。 |
| 學術營運部（Academic Operations） | 社課、學術活動、教材與學習資源。 | 受指派的學術活動、教材與學術公告。 |
| 行銷策略部（Marketing Strategy） | 公開內容、品牌資訊、宣傳與公開頁維護。 | 首頁、公開公告、公開活動頁與宣傳資源。 |

## 三、權限分離的定版原則

| 操作 | 執行者 | 最終確認／限制 |
| --- | --- | --- |
| 書審與面試 | 人才發展部長＋指定幹部。 | 審核紀錄不可覆寫；最終核准不在此權限群組。 |
| 入社最終核准、候補或婉拒 | 社長。 | 核准後才可開啟帳號認證與密碼設定流程。 |
| 專案生指派 | 專案開發部的授權幹部。 | 只能指派有效社員；只影響被指派專案的資料範圍。 |
| 公開內容發布 | 行銷策略部的授權幹部；必要時對外發展部。 | 不可因公開內容權限而讀取會員或專案內部資料。 |
| 幹部職務、任期與跨部門例外 | 社長（暫代網站負責人）。 | 到期前提醒；到期自動回收職務權限並寫入稽核。 |

## 四、開發啟動順序

| 迭代 | 優先實作項目 | 完成判定 |
| --- | --- | --- |
| Iteration 0：骨架 | 升級為具後端、資料庫與認證能力的專案；建立環境、migration、五部門與權限種子資料。 | staging 可部署；資料庫與 RBAC 基線存在。 |
| Iteration 1：身份與招生 | 校內／校外招生梯次、申請、書審、面試、社長最終核准、Email 認證碼、密碼設定。 | UAT 可完成從申請到啟用帳號的完整流程。 |
| Iteration 2：公開與社員服務 | 公開內容、活動、社員檔案與四級資源。 | 訪客與社員可於手機完成核心任務。 |
| Iteration 3：專案與幹部治理 | 專案、專案生指派、五部門資料範圍、任期提醒／撤權、稽核。 | 專案與幹部交接的權限測試通過。 |
| Iteration 4：UAT 與上線 | 資料移轉、跨裝置驗收、錯誤修正、操作手冊、上線演練。 | UAT 完成；production 上線關卡被簽核。 |

## 五、可立即進行與 production 前必做事項

| 類別 | 現在可開始 | production 前的強制門檻 |
| --- | --- | --- |
| 開發 | Wireframe、視覺設計、資料庫、API、前端、staging、UAT。 | 完成端對端、權限、RWD 與資料移轉驗收。 |
| 系統帳號 | 社長可暫代持有 staging 所需帳號與祕密管理。 | 社長簽核「暫時資產持有人、服務清冊、復原方式、續費責任與交接日期」。 |
| D-15 | 列為下一次 MVP 的治理工作。 | 未完成 D-15 時，不得沒有任何復原方案就正式上線；至少需有上述暫行方案。 |
| 組織治理 | 社長暫代網站負責人。 | 在換屆前指定下一任網站負責人並完成權限交接。 |

## 六、實作參數的預設值

這些數值可做成系統設定，第一次部署採以下預設，不必阻塞開發：

| 設定 | MVP 預設值 |
| --- | --- |
| Email 認證碼有效期 | 10 分鐘。 |
| 認證碼錯誤嘗試上限 | 5 次後失效。 |
| 認證碼重寄冷卻時間 | 60 秒。 |
| 幹部任期提醒 | 結束日前 30 天與 7 天各提醒一次。 |
| 活動候補 | MVP 由授權幹部手動遞補，並保留歷程。 |
| 資源下載 | 每次下載均重新驗證公開／社員／專案／幹部範圍。 |

> **結論：** 需求、流程、資料模型、部門權限、RWD、測試與 staging 開發條件均已具備。下一個實作動作是建立具後端、資料庫與認證能力的專案骨架，然後以「身份與招生」作為第一個開發迭代。
